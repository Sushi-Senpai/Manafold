# Card Data — EARS Specs

## Sync Job

- [x] **CARD-001**: When the card-sync job runs, the system shall read the Scryfall `/bulk-data` manifest, download the current `oracle_cards` and `default_cards` exports from the `jsonl_download_uri` each manifest entry names, upsert one `cards` row per Scryfall `oracle_id` and one `card_prints` row per Scryfall printing `id`, and record a `sync_runs` row carrying the source `updated_at`, the upserted row count, and a terminal status.
- [x] **CARD-002**: The system shall store each card's `color_identity` exactly as provided by Scryfall and shall never recompute it.
- [x] **CARD-003**: When ingesting a card, the system shall set `singleton_limit` to `0` if the card's Oracle text states a deck may contain any number of cards with that name, to the stated numeric cap if the text states an "up to N" limit, and to `NULL` (normal singleton) otherwise.
- [x] **CARD-004**: When ingesting a card, the system shall set `can_be_commander` to true if the card's type line contains both "Legendary" and "Creature" or its Oracle text (on any face) contains "can be your commander", and false otherwise.
- [x] **CARD-005**: When ingesting a `default_cards` printing whose `oracle_id` has no matching `cards` row, the system shall skip that printing and count it, rather than failing the run.
- [x] **CARD-006**: Every outbound Scryfall request the sync job makes shall carry a descriptive `User-Agent` identifying Manafold and an explicit `Accept` header, and on an HTTP `429` the job shall wait at least 30 seconds before one retry.
- [x] **CARD-007**: If any step of a bulk ingestion fails, then the system shall mark that `sync_runs` row `failed` with the error text and a `finished_at`, and the job process shall exit non-zero.
- [x] **CARD-008**: The system shall not call any Scryfall `/cards/*` endpoint on a client-facing request path; the sync job's only live Scryfall network calls are the `/bulk-data` manifest and the `data.scryfall.io` bulk-export downloads it names, plus — once CARD-009 lands — an explicit single-printing fallback on card add.

- [x] **CARD-012**: When the sync job ingests a bulk export, the system shall inflate it with gzip (the export is served, and spooled to disk, as `application/gzip` with no `Content-Encoding`) and decode the inflated stream as newline-delimited JSON — one card object per line — processing objects incrementally so the full export is never buffered in memory; a fixture path supplied to the job is uninflated and decoded as either newline-delimited JSON or a single top-level JSON array of card objects (the decoder unwraps a leading `[`).
- [x] **CARD-013**: When the sync job downloads a bulk export, the system shall stream the response body to a temporary file and close the HTTP connection before it performs any database write for that export, and shall remove that temporary file on both the success and the failure path.
- [x] **CARD-014**: When ingesting the `default_cards` export, the system shall bulk-upsert printings — staging every decoded object with `COPY` and merging the batch with a single `INSERT … ON CONFLICT (scryfall_id) DO UPDATE` — rather than issuing a database round trip per printing, resolving each printing's `card_id` by joining `cards` on `scryfall_oracle_id` and counting every unjoined or unparseable printing as skipped (CARD-005).
- [x] **CARD-015**: The sync job shall bound its non-body phases — the manifest fetch and decode with a short overall timeout, and each bulk GET's wait for response headers with a response-header timeout — and shall bound each bulk download with both an idle/read deadline that fails the run if the connection delivers no bytes for a bounded interval and a generous total deadline (~30 min) covering the whole file download as a backstop; none of these bounds shall be a single whole-request HTTP timeout that also spans the subsequent ingest.
- [x] **CARD-010**: When the card-sync job runs, the system shall also read the manifest's `oracle_tags` entry, download that export from its `jsonl_download_uri` (spooled, bounded, and gzip-decoded exactly as the card exports — CARD-012 / CARD-013 / CARD-015), fetch and ingest it only after both the Oracle Cards and Default Cards passes have committed, and record a `sync_runs` row with `bulk_type = 'oracle_tags'`; the tag pass reads a local tag file instead when one is supplied, and is skipped when both card passes read local files and no tag file is supplied, so a fixture run never touches the network.
- [x] **CARD-067**: If any step of the oracle-tags pass fails — a missing `oracle_tags` manifest entry, a download error or timeout, an unreadable tag file, malformed JSON, or an export with no oracle tags — then the system shall record a failed `sync_runs` row with `bulk_type = 'oracle_tags'` and the error text, keep the prior tag snapshot, keep the already-committed card passes, and report the failure without failing the run, so `cmd/cardsync` logs it and still exits successfully.
- [x] **CARD-060**: When ingesting the `oracle_tags` export, the system shall replace the mirrored tag snapshot in one transaction — staging every decoded tag with `COPY`, upserting `oracle_tags` by Scryfall tag `id` (slug, label, description, `parent_ids`, aliases), deleting tags absent from the export, and replacing `card_oracle_tags` with one row per directly tagged (card, tag) pair carrying its `weight` and `annotation` — so re-running on the same export is idempotent and a tag or tagging removed upstream leaves the mirror.
- [x] **CARD-061**: When ingesting the `oracle_tags` export, the system shall skip and count — rather than fail the run on — a tagging whose `oracle_id` is unparseable or matches no `cards` row, and shall skip a tag object whose `type` is not `oracle` or whose `id` is unparseable.
- [x] **CARD-062**: Every oracle-tag "tag or any descendant" read shall resolve the tag's descendants at read time through the `oracle_tag_reach` walk, which starts from the enabled tag(s) with the queried slug, follows child links (the inverse of `parent_ids`), never enters a disabled tag, and terminates even if the tag graph contains a cycle.
- [x] **CARD-063**: The system shall keep a per-tag `disabled` flag that the sync never overwrites, and every oracle-tag read (a card's tags, cards by tag, `otag:` search) shall ignore a disabled tag; a tag-or-descendant read shall match a card only through a path of enabled tags from the queried tag down to a tag applied to the card, so a disabled queried or applied tag matches nothing, a descendant reachable only through a disabled tag drops out, a descendant still reachable through an enabled path stays, and the effect is immediate without a re-sync.
- [ ] **CARD-009**: When a client adds a card by a collector number not present in `card_prints`, the system shall fetch that single printing from Scryfall's `/cards/collection` endpoint (held under ~2 requests/second), upsert it, and then complete the add. (Gap through M2: import resolves by name only; an unmirrored `(SET) collector#` is reported unresolved rather than fetched. Lands with printing-selection UI.)
- [D] **CARD-011**: The system shall mirror non-English printings from the Scryfall `all_cards` export.
- [x] **CARD-040**: When `CARDSYNC_SEED_PATH` (or `CARDSYNC_ORACLE_PATH` / `CARDSYNC_DEFAULT_PATH`) is set, the card-sync job shall ingest that local file — a JSON array of Scryfall card objects — through the same oracle and printing passes as a real bulk run instead of downloading, so a local run and CI have a small set of real cards (with genuine Scryfall `image_uris`, a colour / type / mana-value spread, at least one double-faced card, and at least one card with no image) to search against.
- [x] **CARD-066**: When `CARDSYNC_TAGS_PATH` is set — or `CARDSYNC_SEED_PATH` is set and an `oracle_tags.json` file sits beside the seed file — the card-sync job shall ingest that local file through the same oracle-tags pass as a real bulk run instead of downloading; the checked-in `backend/seed/oracle_tags.json` carries the real Scryfall oracle tags for the seed cards, plus every ancestor of those tags, so a local run and CI can exercise tag queries without a network fetch.

## Search & Autocomplete

- [x] **CARD-020**: When a client calls `GET /api/cards/autocomplete?q=<prefix>`, the system shall return up to 20 card names whose name begins with the prefix (case-insensitively), ordered by ascending `edhrec_rank` with unranked cards last, and shall return an empty list for an empty prefix.
- [x] **CARD-021**: When a client calls `GET /api/cards/search?q=<query>`, the system shall return a page of matching Oracle-level cards from the local mirror, each carrying the card's Oracle fields and its newest printing's image and price data.
- [x] **CARD-022**: The `GET /api/cards/search` query language shall support, over the mirror, bare full-text terms and the `id:` / `id=` / `id>=` colour-identity, `t:` type-line, `cmc` mana-value comparison, `o:` Oracle-text, and `is:commander` predicates.
- [x] **CARD-023**: When a `GET /api/cards/search` query string cannot be parsed, the system shall respond `400` with a message naming the offending token, rather than silently returning unfiltered or empty results.
- [x] **CARD-024**: The system shall serve every `GET /api/cards/*` response from the local mirror only, performing no Scryfall call on that request path (reinforces CARD-008).
- [x] **CARD-064**: The `GET /api/cards/search` query language shall support an `otag:<slug>` (alias `oracletag:`) predicate matching cards tagged with that oracle tag or with any of its descendant tags, case-insensitively on the slug.
- [x] **CARD-065**: The system shall provide queries over the mirror that return a card's directly applied oracle tags (slug, label, weight); the cards carrying a given tag or any descendant tag, optionally within a colour identity, ordered by ascending `edhrec_rank` with unranked cards last; and the subset of a given set of card ids that carry a given tag or any descendant tag.

## Banlist Overrides

- [x] **CARD-030**: The system shall provide a `banlist_overrides` table keyed by card name with a `banned` boolean, which `deck-building`'s legality validator consults after `legalities->>'commander'` so a Panel announcement can be reflected before the next Scryfall refresh.
